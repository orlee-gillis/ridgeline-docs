## Patterns & Workflows

[How LLMs should combine multiple calls to solve real problems]

1. Call `list_ai_identities` to get all identity IDs
2. For each identity, call this API with a high severity threshold
3. Aggregate findings across all identities
4. Flag identities with any critical findings

**Pattern 2: Investigate a single identity over time**
1. Call this API with days_back=7 to get findings from the last week
2. For each finding, call `get_remediation_options` to understand available actions
3. Recommend remediation based on severity and remediation_options
4. Repeat weekly to track trends

**Pattern 3: Detect policy violations**
1. For a known policy violation (e.g., "database tools should never be called from CI/CD"), retrieve findings
2. Filter findings by tool_name and context
3. Alert if violations spike (more than X per day) or involve new identities

## Constraints & Limitations

[Important guardrails for LLM reasoning]

- **Read-only:** This API returns data only. It does not enforce, prevent, or modify future calls.
- **Lookback window:** Findings older than 365 days are not returned. Default is 30 days.
- **Result limit:** Max 1000 findings per call. If you have more, use pagination (not yet supported; contact support).
- **Timing:** Findings are generated with a ~5-minute latency. Real-time detection is not available.
- **Scope definition:** Scope is managed by a separate system. This API cannot read or modify scope declarations directly.
- **Empty results:** If no findings match your criteria, returns `[]` (empty array, not null). This is a normal response.

## Relationship to Other Features

- **get_remediation_options:** For each finding, returns actionable remediation steps. Call this after identifying violations.

## Example: Completed LLM Documentation

```markdown
## `get_unauthorized_access`

**Purpose:**  
Retrieve all instances where an AI identity called tools outside its declared scope. Use this to investigate whether an agent or service account has violated its tool access policy.

**Scope:**  
- INCLUDES: Detects unauthorized calls, assigns severity scores, returns findings with remediation options
- EXCLUDES: Does not enforce or prevent unauthorized calls; read-only reporting only
- PREREQUISITE: Agent identity must be registered with Ridgeline before any tools can be monitored

---

## Parameters

- **`identity_id`** (string, required)  
  The UUID of the AI identity (agent, service account, or model deployment) to query.  
  Obtain by calling `list_ai_identities` and reading the `identity_id` field.

- **`severity_threshold`** (string, optional, default `"medium"`)  
  Return only findings with severity at or above this level.  
  Allowed values: `"low"`, `"medium"`, `"high"`, `"critical"` (case-insensitive).

- **`days_back`** (integer, optional, default `30`)  
  Look back this many days from today. Min 1, max 365.  
  Values greater than 365 are clamped to 365.  
  Must be a positive integer; fractional values are rejected.

---

## Returns

An array of finding objects, each containing:

- **`finding_id`** (string)  
  Unique identifier for this unauthorized access instance. Use this when referencing the finding in alerts or remediation logs.

- **`tool_name`** (string)  
  Name of the tool the identity called (e.g., `"upgrade_subscription"`, `"delete_user"`).

- **`timestamp`** (string, ISO 8601 datetime)  
  When the unauthorized call was made (e.g., `"2026-08-23T14:30:00Z"`).

- **`severity`** (string: `"low"` | `"medium"` | `"high"` | `"critical"`)  
  Risk level assigned by Ridgeline's risk model based on tool sensitivity and context.

- **`context`** (string)  
  Brief explanation of why the call was flagged (e.g., `"Tool not in declared scope"`, `"Called from unexpected geographic region"`).

- **`remediation_options`** (array of strings)  
  IDs of available remediation actions (e.g., `["opt_revoke", "opt_update_scope"]`). Pass these to `get_remediation_options` to see details.

---

## Decision Logic: When to Use This

**Use `get_unauthorized_access` when:**
- You need to find what tools an agent called OUTSIDE its declared scope
- You want to investigate policy violations for a specific identity
- You need severity scoring to prioritize high-risk calls

**Use `get_actual_access` instead when:**
- You need to see ALL calls an agent made (authorized + unauthorized)
- You're building a complete audit trail, not just violations

**Use `get_declared_scope` instead when:**
- You want to see what an agent IS ALLOWED to call (not what it actually called)
- You're checking the agent's current policy, not its activity history
