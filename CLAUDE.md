# CLAUDE.md

This repo is a public portfolio project: a Docusaurus site documenting a
fictional cloud security product, Ridgeline, built to demonstrate a
docs-as-code pipeline with AI-assisted authoring. Nothing described in the
docs is a real product. Treat it accordingly.

## Folder roles

- `docs/` - published pages, the Docusaurus source of truth.
- `ai-workflow/legacy/` - the "before" pages. Evidence, not source.
- `ai-workflow/drafts/` - raw AI output committed unedited. Evidence, not source.
- `ai-workflow/inputs/`, `prompts/`, `decisions/`, `audits/`, `review/` -
  process evidence for the authoring pipeline (what went in, what was asked,
  what was decided, what was checked).
- `ai-workflow/skills/` - skill copies and eval material.
- `static/img/` - images. Reference in Markdown as `/img/filename.jpg`, not
  a relative path.

## Hard rules

- Never edit anything under `ai-workflow/legacy/` or `ai-workflow/drafts/`.
  They are historical evidence, not live content.
- Never edit `ai-workflow/skills/ridgeline-doc-writer/` or
  `ai-workflow/skills/unused-access-expert/` until the session 21 baseline
  score is recorded. If you don't know whether it's recorded, ask instead of
  assuming.
- Never invent product facts. If a claim about Ridgeline's behavior isn't
  confirmed by existing docs or the user, flag it inline as
  `[VERIFY: what needs confirming]` rather than guessing.
- Every change goes on a branch and through a pull request. Never commit
  directly to `main`.
- Never print, echo, or commit secrets or tokens.

## Conventions

- Filenames and file extensions are lowercase.
- `sidebars.js` is manual, not autogenerated. A new page in `docs/` needs an
  explicit entry there or it will not appear in the nav.
- Local dev: `npm install`, then `npm start`.
- Never edit anything in `ai-workflow/legacy/`. Those files are deliberately unpolished - they are
  the "before" in a before/after comparison, and tidying them destroys the evidence.

## Frozen skills

`ridgeline-doc-writer` and `unused-access-expert` are frozen until the Phase F baseline eval is
recorded (roadmap session 21). No edits to either skill before then.

## Skills Freeze

The following skills are frozen until the Phase F baseline evaluation is recorded 
in Session 21:

- `ridgeline-doc-writer`
- `unused-access-expert`

Do not edit these skills during Sessions 19–20. Session 21 measures their output 
against this baseline state. After Session 21, these skills are open for iteration.

## Gates

CI gates fall into three tiers - see `.claude/gates-architecture.md` for the full picture:

1. **Deterministic** - Vale, markdownlint, lychee, the Docusaurus build. Fast, cheap, no model call.
2. **AI-advisory** - `review-docs.py`. Comments on a PR, never blocks.
3. **AI-blocking** - `audit-report.js` and the `validate-*.py` scripts. Can fail the PR check.

Every gate is designed in `GATES-DESIGN.md` before it's implemented, and its status is tracked in
`GATES.md` (inventory) and `GATES-CHANGELOG.md` (history and reasoning). If you're adding a new gate,
follow that sequence - don't write the workflow file first.

## Skill triggers

When a user's request matches one of these, load the corresponding skill before responding:

| The user says something like... | Load |
| --- | --- |
| "review this page", "audit this", "what's wrong with X" | `ai-workflow/skills/ridgeline-doc-auditor/SKILL.md` |
| "draft a page for X", "write documentation for X" | `ai-workflow/skills/ridgeline-doc-writer/SKILL.md` (frozen - see Hard rules) |
| A factual question about Unused Access behavior | `ai-workflow/skills/unused-access-expert/SKILL.md` |

See `.claude/skill-selection.md` for more examples and edge cases.
