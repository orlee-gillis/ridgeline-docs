## Text, before and after

Each row is one element of the page, in the order it appears from top to bottom.

| Element | Before (AI draft) | After (my edit) |
| --- | --- | --- |
| Headline | Find the access your integrations never use. Remove it safely. | See how much of your environment your integrations can reach, and how much they use. |
| Intro paragraph | Every integration starts with a grant, and few are ever revisited. Unused Access shows which integrations hold access they never touch, ranks them by how much of your environment they can reach, and recommends narrower access that keeps them working. | Integrations often hold permissions they never use, and if one is compromised, an attacker inherits all of them. Unused Access shows you which permissions those are, so you can remove them safely, without breaking a workflow or removing the wrong ones. |
| Second heading | Start with the access that matters most, not the longest list. | Prioritize the integrations that could do the most damage if compromised, not the ones with the longest list of unused permissions. |
| Card 1 | **Ranked by reach.** Rows sort by Reach score, so the first screen holds the integrations where unused access matters most, not the ones with the biggest raw counts. | **Ranked by Reach score.** Integrations are ordered according to Reach score, immediately showing you the integrations where unused access matters most |
| Card 2 | **Safer to act on.** Recommendations propose narrower access that keeps the integration working. Rights the logs cannot audit count as used and are never removed. | **Safe to remove.** Each recommendation proposes narrower permissions that still keep the integration running smoothly. Permissions that the activity logs can't verify are treated as used and are never recommended for removal. |
| Card 3 | **No new permissions.** Unused Access reuses the permissions granted when each integration was connected and reads activity logs you already have. | **No permission renewal needed.** Unused Access works from the access and activity logs you already have, so nothing extra needs to be granted. |
| Steps heading | From finding to fixing in three steps | From usage finding to permission fine-tuning in three steps |
| Step 1 | **Open the report.** Go to Access Center, then Exposures, then Unused Access. Filter to service accounts or export a CSV if you need it. | **Open the report.** Go to Access Center > Exposures > Unused Access. Start with the integrations at the top, since their exposure would cause the most severe damage. |
| Step 2 | **Review the grants.** Open an integration and its Access tab to see which grants reach it and which of their rights go unused. | **Find the unused permissions.** Open an integration's Access tab to see which of its permissions it never uses. |
| Step 3 | **Apply narrower access.** Review the proposed alternative and apply it, keeping the integration working with less access. | **Apply the recommended remediation.** In the same Access tab, review the remediation that narrows permissions to only the ones the integration uses, then apply it. |
| Closing heading | Ready to see what your integrations are not using? | Want to learn how Unused Access finds the permissions your integrations don't use? |
